# Eazy-share

Send files or whole folders to other devices on the same Wi-Fi. A browser extension starts and stops a small local server; everyone else just opens a link in their browser, with nothing to install.

Everything you edit is TypeScript (Node 22+). `npm run build` compiles it into `dist/`.

## What runs where

| Role | Works on |
| --- | --- |
| **The computer that shares** (runs the extension and the server) | Windows, macOS, Linux, with Chrome, Edge, Brave or Chromium |
| **Any other device** (sends and receives through the web page) | Android, iOS and iPadOS, Windows, macOS, Linux: any browser from the last five years or so (Chrome, Safari, Firefox, Edge, Samsung Internet) |

Phones and tablets can send and receive files; to send a whole **folder**, use a computer (mobile browsers can only pick files). Received zips land in the browser's downloads (the Files app on iPhone and iPad).

## Set up (once)

```bash
npm install
npm run install-host      # builds, then registers the bridge between the extension and this project
```

Then load the extension: open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked** and choose the **`dist/extension`** folder. Works in Chrome, Brave, Edge and Chromium on Windows, macOS and Linux.

`install-host` writes a small launcher into `~/.eazy-share/bin/` (`eazy-share-host.cmd` on Windows) and registers it with each installed browser. On macOS and Linux that is a manifest in the browser's `NativeMessagingHosts` folder; on Windows it is a registry key under `HKEY_CURRENT_USER` (no administrator rights needed). Re-run it if you move this folder or change Node versions. `node dist/node/cli/main.js uninstall-host` removes it.

Windows and macOS may show a firewall prompt the first time the server starts: choose **Allow** (on Windows tick *Private networks*), or other devices can't connect.

## Use

1. Click the extension icon and press **Start sharing**. It shows an address like `http://192.168.1.2:8787`.
2. On the other device (same Wi-Fi), open that address in a browser. The extension lists these steps too, under "On the receiving device".
3. On the sharing page: pick files or a folder, tick the devices that should receive it, press **Zip & send**.
4. Receivers get a notice and a **Received** list; they tap **Download** and open the `.zip`.

Without the extension you can run `npm start` (foreground) or `node dist/node/cli/main.js start | stop | status`.

## Layout

```
src/                 everything you edit (TypeScript, plus a few static files)
  shared/            types used by every part (API shapes, native-messaging messages)
  node/
    core/            business logic, no HTTP: devices (presence), transfers (stage -> zip -> inbox), paths, zip
    http/            router, request context, API endpoints, event stream, static files
    runtime/         starts/stops the server as a detached background process (state file, health check)
    native/          native-messaging protocol, host commands, installer
    cli/             argument parsing and commands
    build/           copies HTML/CSS/manifest/icons into dist after compiling
    testing/         helpers shared by the tests
  web/               the sharing page: typed modules + index.html, style.css
  extension/         the popup: typed modules + manifest.json, popup.html, popup.css, icons
dist/                generated by `npm run build`; never edit
  node/              compiled server, host and CLI
  web/               the page the server serves
  extension/         the extension to load in the browser
build/               generated type declarations and build caches; never edit
```

Each of `shared`, `node`, `web` and `extension` is its own TypeScript project (`tsc -b` builds all). `shared` is types only, so the browser code and the server can't drift apart on API shapes. Tests sit next to the code they cover (`*.test.ts`).

The `.js` files in `dist/` are what browsers, Node and Chrome actually run (none of them can run TypeScript directly), so they are generated and gitignored.

## How it works

- **Extension to server:** the popup uses Chrome native messaging. Each click starts the registered host, sends one command (`status`, `start`, `stop`), gets one JSON reply, and the host exits. `start` launches the real server as a detached process, so it keeps running after the host (and the browser) exit. It tracks it in `~/.eazy-share/state.json` and picks another port if the default is busy.
- **Who is online:** each page keeps a Server-Sent Events connection open (`/api/events`). An open connection means the device is online; the server pushes the updated device list to everyone. Devices are known to each other by a public id only.
- **Sending:** the browser uploads each file into a private staging area, then asks the server to zip it (streamed) and deliver it to the chosen devices' inboxes. Folders keep their structure.
- **Receiving:** each device has an inbox in server memory. Dismissing removes it for that device; the zip is deleted once every recipient dismissed it, or after 24 hours. Everything is wiped when the server restarts.

## Develop

```bash
npm test          # builds, then runs all tests (unit + real-server integration + the launcher)
npm run build     # type-check and compile everything into dist/
npm run clean     # delete dist/ and build/
```

If you change `src/extension/manifest.json`'s `key`, update `EXTENSION_ID` in `src/node/core/config.ts` too (a test checks they match). After editing extension code, rebuild and press the reload button on the extension in `chrome://extensions`.

## Security notes

There is no login. Any device on your network can open the page, appear in the list and send to others. A device's private id (kept in the browser's localStorage) is what authorises downloads from its own inbox. Use it on networks you trust and press **Stop sharing** when done. Uploaded paths are sanitised so nothing can be written outside the staging folder. The native host only accepts messages from this extension's ID.

Known limits:
- Firefox can't host (the extension is for Chromium-based browsers), but Firefox works fine on the receiving devices.
- On Windows, **Stop sharing** ends the server immediately rather than gracefully; nothing is lost, since transfers are temporary anyway.
- Empty folders aren't included in the zip (only files are).
- File names Windows can't create (`CON`, `NUL`, a trailing dot) are renamed inside the zip, on every platform.
